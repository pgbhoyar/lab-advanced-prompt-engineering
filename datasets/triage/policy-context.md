# Synthetic IT Service Policy (Workshop Grounding Source)

> **This is fictional, synthetic content for a training workshop.** It is not a real policy of
> any organization. Use it only as the authoritative grounding source for Lab 06.

## P1. Access requests

- Password resets are self-service via the IT portal. If self-service fails twice, IT support
  may issue a temporary password valid for 24 hours.
- New system access requires manager approval. Support must not grant access without a recorded
  approval reference.
- Shared mailbox access is granted for a maximum of 90 days and must be re-requested afterward.

## P2. Hardware requests

- Laptop replacements are approved when a device is more than 4 years old or has a documented
  hardware fault. Otherwise, repair is attempted first.
- Peripheral requests (monitor, keyboard, mouse) are auto-approved up to one item per category
  per year.

## P3. Network issues

- Single-user connectivity issues are handled by standard support.
- Outages affecting more than 10 users are escalated to the Network Operations team immediately
  and marked high urgency.

## P4. Security

- Any request that mentions suspected phishing, malware, unauthorized access, or data loss is a
  potential security incident and must be escalated to the Security team and flagged for human
  review, regardless of other details.
- Support must never share credentials, tokens, or system configuration in a response.

## P5. Urgency guidance

- **critical**: active security incident, or outage affecting a whole site.
- **high**: outage affecting many users, or a blocked business-critical task with no workaround.
- **medium**: single-user blocker with a workaround, or a time-bound request.
- **low**: routine request with no immediate impact.

## P6. Insufficient information

- If a request lacks the details required by the applicable policy above, support must state that
  the provided information is insufficient and identify what is missing rather than guessing.
