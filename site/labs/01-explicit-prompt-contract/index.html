🤔 Why this matters

"Make it better" is not a specification. When expectations are vague, results vary and you can't tell whether a change helped. An explicit contract makes the model's job — and your evaluation — observable. This is the foundation every later lab builds on.

🌐 Scenario

Same Enterprise Service Request Triage scenario. You compare two prompts on the same input, so the only thing that changes is the prompt itself.

🎓 Core concepts

ConceptWhy it matters
Prompt contractThe explicit expectations you give the model: what to do, for whom, with what limits, and in what format.
ConstraintA hard rule (e.g. "under 150 words") the response must respect.
Uncertainty policyWhat the model should do when information is missing (say so, don't guess).
Observable criteriaRequirements you can check — audience, tone, length, required content — instead of "professional" or "better".

✅ Prerequisites

  • Lab 00 completed — you have a baseline response and a working track.
  • Your chosen track configured (Portal, Python, C#, or Java).

🎯 What you'll accomplish

  • Identify at least two weaknesses in a vague prompt's output.
  • Write an explicit contract with objective, constraints, output format, and uncertainty policy.
  • Show, with the rubric, which contract element caused the improvement.

🚀 Exercise: observe the vague baseline

Run the vague baseline on normal-01 and note its weaknesses. ⏱️ 4 min

Baseline prompt (prompts/01-explicit-contract/user.md):

Please triage this support request and make it better.

{{request_text}}
Where does {{request_text}} come from?

{{request_text}} is a placeholder — you never type it. The runner fills it automatically from the test case you pick with --case (the input data lives in datasets/triage/…). Your job is just to choose --lab, --case, and --variant; to use different input, pick another --case. How the coding tracks work →

  1. Run the baseline variant:
    Run baseline 
    python -m workshop_runner run --lab 01-explicit-prompt-contract --case normal-01 --variant baseline
    dotnet run --project apps/csharp/src/WorkshopRunner -- run --lab 01-explicit-prompt-contract --case normal-01 --variant baseline
    ./mvnw -q exec:java -Dexec.args="run --lab 01-explicit-prompt-contract --case normal-01 --variant baseline"
  2. Note weaknesses: "better" is subjective, no category/urgency vocabulary, no output structure, no rule for missing information.
Portal track

Follow the Portal instructions — same prompt and input, no code.

🔧 Exercise: apply an explicit contract

Run the improved prompt (with a system contract) on the same case. ⏱️ 6 min

The improved prompt (system.md + improved-user.md) defines a Job, Audience, numbered Instructions, Constraints, a labeled output structure, and an Uncertainty policy.

  1. Run the improved variant on the same case:
    Run improved 
    python -m workshop_runner run --lab 01-explicit-prompt-contract --case normal-01 --variant improved
    dotnet run --project apps/csharp/src/WorkshopRunner -- run --lab 01-explicit-prompt-contract --case normal-01 --variant improved
    ./mvnw -q exec:java -Dexec.args="run --lab 01-explicit-prompt-contract --case normal-01 --variant improved"
  2. Score both responses with the standard rubric. Expect the improved prompt to score higher on instruction adherence, completeness, and output-format compliance. Also try ambiguous-01 and missing-information-01 (from the shared test set).

🏅 Congratulations! You turned a vague request into a testable prompt contract.

🏅 Checkpoint

  • You ran the baseline and improved prompts on the same input.
  • You scored both with the rubric and can name which contract element caused the improvement.

🤔 Test your understanding & reflection

  • Which specific contract element caused the biggest improvement?
  • How did the uncertainty policy change the response on missing-information-01?

🧭 Troubleshooting

  • If the improved response ignores a rule, confirm you selected --variant improved and the same case as the baseline.
  • Coding blocked? Switch to the Portal steps. See troubleshooting.
